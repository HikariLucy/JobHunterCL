# M2.2 Implementation Plan

**Goal:** oferta guardada → evidencia documental → decisiones individuales → nueva copia LaTeX privada.
**Spec:** solicitud M2.2 del usuario y docs/CV_INTEGRACION.md (contratos M2.1).
**Architecture:** analizador determinista; motor de ediciones acotadas; almacenamiento de planes separado bajo cv/tailoring con primitivas POSIX existentes; router y pantalla React.
**Tech Stack:** Python/FastAPI/Pydantic, React/TypeScript, sin dependencias nuevas.

## Restricciones globales

Solo fixtures sintéticos. Sin IA externa, red documental, TeX, PDF, envío, push o merge. Maestro inalterado; snapshot bytes exactos y SHA-256. Offsets Python Unicode. Cache no-store. Windows falla cerrado. Trabajar en rama de desarrollo actual solicitada; no modificar main.

## Decisiones de diseño

La especificación detallada del usuario autoriza implementar incrementalmente sin otra ronda de aprobación. Se trabaja en el checkout limpio solicitado. No se duplican parser, matching de términos ni primitivas privadas. No se genera reformulación: una cita no prueba equivalencia. Solo viñetas completas planas en experience/projects/skills son editables; comandos desconocidos, condicionales, inclusiones, macros definidas y estructura ambigua bloquean generación. Coincidencia literal significa mención documentada, nunca certificación de cumplir requisitos compuestos, años o títulos. El idioma recomendado es revisable sin traducción automática.

## Foco de revisión

- Texto negado/en aprendizaje no acredita la tecnología.
- Comandos ocultos en comentarios y spans después de Unicode/BOM/CRLF.
- Snapshot disponible después de sustituir/eliminar maestro.
- Aprobar cambios superpuestos bloquea generación y muestra conflicto.
- Peticiones atrasadas, revisión concurrente y generación sin preview revisado.
